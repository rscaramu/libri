# Capitolo 22 — Issue e organizzazione del lavoro

## Prompt 1 — Trasformare una segnalazione in issue.

```text
Un utente mi ha scritto questa email:
[incollate il testo]
Riscrivila come issue di GitHub con titolo chiaro,
sezioni "Passi per riprodurre", "Comportamento atteso",
"Comportamento osservato" e "Ambiente", e proponi le
etichette da applicare. Segnala le informazioni che
mancano e che dovrei chiedere.
```

## Prompt 2 — Progettare le etichette.

```text
Il mio progetto e' un'applicazione web con backend
Python, frontend React e documentazione. Proponi uno
schema di etichette in tre famiglie (tipo, area,
priorita') con colori e descrizioni, e i comandi
"gh label create" per crearle tutte.
```

## Prompt 3 — Modello di issue.

```text
Scrivi un file .github/ISSUE_TEMPLATE/richiesta.yml in
formato issue form per le richieste di funzionalita',
con campi: problema da risolvere (obbligatorio),
soluzione proposta, alternative considerate, e una
casella "sono disponibile a implementarla".
```

## I limiti

L’IA scrive ottime issue dai vostri appunti, ma non può riprodurre l’errore né sapere se è già stato segnalato: cercate tra le issue esistenti prima di aprirne una. E le priorità sono decisioni vostre, non dell’assistente.
