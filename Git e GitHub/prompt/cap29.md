# Capitolo 29 — Codespaces, Projects, wiki e organizzazioni

## Prompt 1 — Un dev container.

```text
Scrivi un devcontainer.json per un progetto con backend
Python 3.12 (FastAPI), frontend Node 20, PostgreSQL 16
come servizio e Redis, usando docker-compose, con le
estensioni VS Code per Python ed ESLint, e i comandi
per installare le dipendenze alla creazione.
```

## Prompt 2 — Struttura dell’organizzazione.

```text
Stiamo creando un'organizzazione GitHub per un'azienda
di 40 sviluppatori in 5 squadre di prodotto piu' una
di piattaforma. Proponi la struttura dei team (con
annidamento), i permessi predefiniti sui repository,
che cosa mettere nel repository .github e quali
ruleset a livello di organizzazione.
```

## Prompt 3 — Automazioni di un progetto.

```text
Voglio un progetto GitHub con colonne Da fare, In
corso, In revisione, Fatto, che si aggiorni da solo:
issue nuove in Da fare, issue con PR aperta in In
revisione, PR unite in Fatto, e un campo Iterazione
di due settimane. Spiega quali automazioni integrate
usare e per quali serve un workflow di Actions.
```

## I limiti

Le funzioni della piattaforma cambiano spesso, e i piani a pagamento ancora di più: ciò che l’IA descrive può essere stato rinominato o spostato. La struttura di un’organizzazione dipende da come lavorate davvero: la proposta dell’assistente è un punto di partenza da adattare.
